# ADR 0007: Python 3.13 e 3.14 suportados

Estado: aceite
Data: 2026-11-20

## Contexto

O ADR 0004 fixou o Python 3.13. Na prática, os dois computadores de desenvolvimento têm versões diferentes: um tem o Python 3.13 e o outro o 3.14. A documentação do Django 6.1 diz que suporta o Python 3.12, 3.13 e 3.14, e os testes passam nas duas versões. A documentação e o CI diziam só 3.13, o que não correspondia à realidade.

## Decisão

Suportamos o Python 3.13 e o 3.14. O CI corre as verificações nas duas versões, e o README aceita qualquer uma. O mínimo continua a ser o 3.13, que é também o alvo do Ruff.

O check `qualidade`, que a proteção do ramo `main` exige, passa a ser um trabalho final que só passa se os testes passarem em todas as versões. Assim a proteção não precisa de mudar.

## Alternativas consideradas

- Só 3.13: obrigava a instalar uma segunda versão do Python no computador que traz a 3.14.
- Só 3.14: não existe no computador que traz a 3.13.
- Testar só na 3.13 e afirmar que a 3.14 também serve: seria uma promessa sem prova.

## Consequências

- O CI faz o dobro do trabalho, em paralelo e sem custo adicional (repositório público).
- Qualquer dependência nova tem de funcionar nas duas versões.
- Quando sair uma versão nova do Python, ou o Django mudar a lista de versões suportadas, este ADR é revisto.
